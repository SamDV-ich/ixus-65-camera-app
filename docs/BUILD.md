# Сборка, упаковка и проверка

Проверенная среда: Intel macOS Ventura 13.7.8, Swift 5.8.1 / Apple Command Line Tools. Конечному пользователю достаточно готового .app; перечисленные ниже зависимости нужны разработчику. Автоматическая установка зависимостей не выполняется.

## Пути

Проект: `/Users/dmitrysamoilovich/chdk-work/ixus-capture`.

`scripts/paths.sh` использует родительскую папку как рабочую область. На этом Mac там уже находятся:

| Переменная | Значение по умолчанию |
| --- | --- |
| IXUS_WORK_ROOT | родитель папки проекта |
| CHDK_ORIGINAL | `$IXUS_WORK_ROOT/tools/chdkptp` |
| LUA_SOURCE | `$IXUS_WORK_ROOT/tools/lua-5.2.4` |
| LUA_PREFIX | `$IXUS_WORK_ROOT/tools/lua52` (include и lib/liblua.a) |
| LUA_BIN | `$LUA_SOURCE/src/lua`, для имитатора Lua |
| LIBUSB_COMPAT_PREFIX | `/usr/local/opt/libusb-compat` |
| LIBUSB_PREFIX | `/usr/local/opt/libusb` |
| BUILD_DIR | `$IXUS_WORK_ROOT/builds/ixus-capture` |
| APP_PATH | `$BUILD_DIR/IXUS Camera.app` |

Эти переменные можно задать в окружении при другом расположении зависимостей. Команды ниже проверены с текущими значениями. Сам проект можно перемещать внутри рабочей области, задав IXUS_WORK_ROOT при необходимости; исходный `chdkptp/config.mk` содержит абсолютные пути к существующим Lua/libusb и не переносится/не переписывается. Во временной копии сборки пути передаются make явно.

## Команды

```bash
cd /Users/dmitrysamoilovich/chdk-work/ixus-capture
./scripts/test.sh
./scripts/build.sh
./scripts/verify.sh
```

Обычный `test.sh` работает только с имитаторами и не подключается к камере. Скрипты запускаются из любой текущей папки: они сами переходят в корень проекта. Итог: `../builds/ixus-capture/IXUS Camera.app`. Повторная сборка заменяет только эту сгенерированную сборку после проверки новой подписи; каталог временной компиляции удаляется. Прежняя установленная копия исходников и локальный CHDKPTP не меняются. Перед обновлением запущенное приложение лучше закрыть и затем открыть свежую сборку из Finder.

Сборка:

1. Проверяет наличие локальных зависимостей.
2. Копирует CHDKPTP во временный каталог, применяет `Resources/chdkptp-safe-usb.patch` и компилирует обработчик.
3. Собирает SwiftUI для `x86_64-apple-macosx13.0`.
4. Вкладывает обработчик, Lua-модули, адаптер, две USB dylib, лицензии и исходники CHDKPTP/Lua.
5. Меняет пути загрузчика на `@executable_path` / `@loader_path` внутри пакета; подписывает ad-hoc.
6. Проверяет подпись, затем размещает приложение в builds/ixus-capture вне репозитория.

`verify.sh` проверяет Intel-архитектуру, подпись, Info.plist, вложенные ресурсы/лицензии и отсутствие путей Homebrew в зависимостях загрузчика. Публичный релиз с Developer ID/notarization и полным комплектом соответствующих исходников сторонних компонентов пока не подготовлен. Лицензии находятся в `.app/Contents/Resources/Licenses`; для исходников см. `Resources/Sources` внутри пакета.

## Аппаратные проверки — отдельное действие

Следующие команды уже использовались для этих типов проверок, но после переустройства папок повторно на камере не запускались: при переносе проверялись сборка и имитаторы. Запускать только после подготовки камеры и согласования физического теста. Приложение и другие клиенты камеры должны быть закрыты.

```bash
./scripts/test.sh --camera
./scripts/test.sh --display
```

`--camera` временно меняет вспышку и зум с восстановлением, проверяет Live View/одно соединение; фотографий не делает. `--display` временно переводит камеру в просмотр, затем запускает Live View, выключает подсветку на 15 секунд, проверяет опрос и возвращает просмотр/зум; перед выходом проверяет включение подсветки через завершение обработчика. Этот тест оставляет камеру в просмотре. Физическое потемнение и восстановление экрана подтверждает наблюдатель. При обрыве питания восстановление не гарантируется.

`Tests/CameraIntegration.swift` — исторический дополнительный сценарий; требует начального AUTO и содержит отдельную опцию `--capture`, которая делает один настоящий снимок. Обычный test.sh его не запускает. Выходные снимки такого ручного теста идут в IXUS_TEST_OUTPUT_DIR либо во временную папку `ixus-capture-checks`, а не внутрь .app. Не использовать его как универсальное восстановление камеры. Старый `../artifacts/checks/check_camera.py` также относится к конкретному историческому испытанию и не входит в штатную проверку.

## Контроль внешних зависимостей

Внешние CHDKPTP и Lua находятся в tools рабочей области либо задаются переменными окружения. Они не входят в исходный репозиторий приложения. Старые абсолютные пути рабочей области сохранены совместимыми ссылками. Готовый пакет включает необходимые компоненты для конечного пользователя.

### Проверка удержания подсветки (0.4.1)

После отдельного согласования физической проверки, при закрытом приложении: `./scripts/test.sh --backlight-policy`. Выполняются Auto/P, просмотр/съёмка и временное включение подсветки вне политики, чтобы проверить повторное выключение при poll. Тест восстанавливает исходные режим/вспышку/зум/AF Lock, включает подсветку и закрывает соединение, не делая фотографий. Требуется подтверждение наблюдателем потемнения и восстановления экрана; это не проверка физического переключателя режимов камеры. Тело теста выполнено на настоящей камере, проверенные возможности описаны в [STATUS.md](STATUS.md). Запуск нового флага оболочки отдельно не повторялся, чтобы не проводить ещё один ненужный аппаратный тест.
